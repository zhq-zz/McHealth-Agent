- **目标**：确定差异化选题
- **产出**：确定"营养配餐 + 过敏原筛查"方向，面向减脂/控糖/食物过敏人群
- **WorkBuddy 使用**：需求梳理、竞品差异化分析、技术方案选型

```text
要点记录：
- 选题差异化：大多数作品只算热量，本项目把「过敏原安全」作为第一道闸门
- Demo 形态：Python 命令行程序，零前端依赖
- 核心约束：热量上限 / 预算上限 / 过敏原黑名单
```

### 阶段 2：项目脚手架与文件结构（2026-10-12）

- **目标**：搭建项目目录与基础文件
- **产出**：README.md、MCP_INTEGRATION.md、CONTEST_DECLARATION.md、mcp-config.example.json、.gitignore、requirements.txt、src/ 三个源码文件、docs/ 本日志

要点记录：

### 阶段 3：MCP 客户端开发（2026-10-12）

- **目标**：封装麦当劳 MCP 的 4 类接口
- **产出**：src/mcp_client.py
- **WorkBuddy 使用**：接口封装、异常处理、Token 脱敏、字段兼容归一化

```text
要点记录：
- 封装 get_menu / get_nutrition / get_allergens / get_price
- 统一异常捕获：超时重试、HTTP 4xx/5xx 降级、JSON 解析失败兜底
- 安全优先：过敏原字段缺失时标记 allergen_known=False
- 实测修正：麦当劳 MCP 为标准 Streamable HTTP 协议（非 REST），
  端点 https://mcp.mcd.cn，tools/list 返回 35 个工具
```

### 阶段 4：推荐引擎开发（2026-10-13）

- **目标**：实现过敏原过滤 + 热量预算筛选 + 营养汇总
- **产出**：src/recommender.py
- **WorkBuddy 使用**：算法设计、数据结构定义、报表渲染

```text
要点记录：
- 三步法：过敏原过滤 → 热量/预算筛选 → 营养与价格汇总
- 过敏原中英文别名归一（花生→peanuts / 牛奶→milk ...）
- 修复单字别名子串误判（"蛋糕"→鸡蛋、"奶茶"→牛奶），别名 key 长度须 ≥2
- 三层过敏原策略：餐品名守卫 → 配料推断 → 未知项策略（strict / warn）
- 组合策略：主餐为锚 + 配餐 + 饮料，在双重上限内贪心填充
```

### 阶段 5：命令行入口与联调（2026-10-13）

- **目标**：打通"自然语言 → 数据获取 → 推荐 → 打印"全流程
- **产出**：src/main.py
- **WorkBuddy 使用**：自然语言解析、CLI 参数设计、结构化输出

```text
要点记录：
- 支持中文自然语言解析热量/预算/过敏原
- 支持 --mock 离线自测，方便无 Token 时演示
- 新增 --list-tools 工具发现、--allergen-policy 策略切换
- 方案B：遍历 query-meals 全量餐品并调用 query-meal-detail 拆解套餐，
  营养命中率由 19/115 提升至 82/115
```
